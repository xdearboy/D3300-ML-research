# D3300-ML Research — Nikon D3300 C 1.02

Исследовательский проект по статическому анализу B-firmware Nikon D3300 C 1.02 и прототипированию архитектуры расширений в хостовом симуляторе.

> Важно: репозиторий не содержит устанавливаемую прошивку или проверенный загрузчик ARM-кода. Ничего из `payload/`, `core/dml_draw_buffer.*`, `core/dml_camera_status_hw.*` и `modules/` нельзя считать готовым для запуска на камере.

## Подтверждённые результаты

- Декодирование контейнера C 1.02 и воспроизводимые хеши извлечённых компонентов.
- ARM/Thumb ELF-инструменты, индекс поиска, Ghidra-скрипты и тестовые фикстуры.
- Идентификация объекта `CKRRCCameraStatus` по RAM `0x10491580`, vtable `0x9151F6F0` и RTTI. Подтверждено кольцо 8-байтных битовых снимков; байты объекта `+0x8C..+0x98` являются индикаторами переходов, а не прямыми параметрами съёмки. Семантика битов пока не установлена.
- Статически прослеженные участки `RelayEventEx`, `COPNOQueueButton`, 16-байтной записи состояния кнопок и `CSYSCAppButtonController`. Привязка большинства числовых кодов к физическим кнопкам остаётся кандидатной.
- Таблица DrawBuffer по `0x104A0868`: 20 записей с шагом 20 байт и несколько наблюдаемых операций. Формат пикселей, точные поля записи и безопасный callback/hook не установлены.
- Признаки T-Kernel в B-firmware. Точные syscall ABI, task IDs и безопасная схема загрузки модуля ещё требуют проверки.

Подробные доказательства и границы выводов находятся в `reports/`. Адрес считается подтверждённым только при наличии воспроизводимого дизассемблирования или проверки ожидаемых байт.

## Хостовые прототипы

Следующие компоненты нужны для проектирования и тестирования интерфейсов, но не доказывают совместимость с камерой:

- меню и модель жизненного цикла `payload`;
- ARGB8888-рендерер и BMP/PPM-экспорт;
- экран параметров съёмки;
- focus peaking, zebra и histogram на синтетическом буфере;
- T-Kernel task/message-buffer simulator;
- экспериментальный генератор 700-байтных Picture Control файлов.

Совместимость генерируемых `.NOP/.NCP` с Nikon не подтверждена эталонными файлами или независимым парсером. Не импортируйте их в камеру.

## Сборка и тесты

```bash
make clean && make test
```

Это запускает хостовый симулятор, C unit-тесты и Python-тесты. Успешные тесты подтверждают поведение моделей, а не аппаратную совместимость.

```bash
./build/d3300_sim --interactive
./build/d3300_sim --screenshot-info info_screen.bmp
./build/d3300_sim --screenshot-assist assist_preview.bmp
```

Экспорт Picture Control предназначен только для записи в тестовый каталог:

```bash
./build/d3300_sim --export-fuji-profiles /tmp/d3300-profile-fixtures
```

## Правила исследования

- не создавать устанавливаемую прошивку и не выполнять операции с камерой;
- не объявлять адрес, ABI, формат или код кнопки подтверждённым без дизассемблирования;
- отделять наблюдаемый факт, гипотезу и хостовую модель;
- поддерживать `make test` и делать отдельные Git-коммиты;
- не включать оригинальные firmware blobs в Git.

Текущий безопасный следующий шаг — восстановить реальные структуры сообщений и DrawBuffer по потребителям/производителям, после чего обновлять модели только на основании найденных инструкций.
