# Nikon D3300 C 1.02 — проверка загруженной прошивки

Статус: **read-only анализ реального файла, полученного от пользователя**. Это НЕ кастомная прошивка Nikon, нет проверенного хука, загрузчика или работающего на камере модуля. **Ничего из результатов не устанавливать на фотоаппарат.**

## B firmware — карта кода

- CPU: ARMv7 little-endian.
- ROM/base: `0x90020000`.
- Вектор старта: в заголовке B по смещению `0x20` хранится адрес `0x90352FE0`.
- По адресу `0x90352FE0` — ARM инструкция `LDR PC, [PC, #0x1E0]`; это переход к `0x90352FE8` (по литерному слову на `0x903531C8`).
- По адресу `0x9035303C` — `BIC R2, R2, #3`, по адресу `0x90353040` — `BL 0x903532A0`. Анализ окружения показывает повторяющийся блок копирования ROM→RAM; `0x903532A0` является кандидатом в процедуру копирования памяти. Вывод о её назначении основан на последовательности инструкций и вызовов, а не на выполнении в камере.

Реально присутствующие ROM→RAM копирования, ранее указанные Nikon Hacker:

| ROM (источник) | RAM (цель) | Размер | Предполагаемое назначение |
|---|---|---:|---|
| `0x9158A358` | `0x10000000` | `0x3B5B4` | kernel code (rwx) |
| `0x915C590C` | `0x1003B5B4` | `0x179C` | data |
| `0x916A73A0` | `0x1011D420` | `0x28B3C` | data |
| `0x916A739C` | `0x1011D03C` | `0x4` | data |

## Аудит Nikon Hacker C 1.02

Проверены все **23** известные адреса, занесённые в `tools/d3300_recon.py`:

- **20/20** мест патча на повышенный битрейт видео — статус `original`;
- **3/3** мест патча тайм-аута Live View — статус `original`;
- несовпадающих, смешанных или выходящих за границы файла нет.

Это подтверждает соответствие **известным байтовым константам** C 1.02. Наличие этих мест НЕ доказывает существование безопасного execution hook.

## Дополнительные ориентиры в образе

Найдены *строки*, не доказанные исполняемые вызовы или интерфейсы API:

| ROM | Строка | Комментарий |
|---|---|---|
| `0x90027190` | `RelayEventTask.cpp` | полезный ориентир для анализа событий |

| `0x90A9202D` | `TXT_1_Sht_List18_IntervalTimerShooting` | строка из набора ресурсов; **не доказательство доступного интервального режима** |
| `0x91281FF9` | `JpegEncodeStart` | полезный ориентир для исследования JPEG |
| `0x9003D4EC` | `NIKON D3300` | подтверждающая идентификационная строка |

Простой поиск 32-битных ссылок на эти адреса не выявил прямых адресных указателей. Возможны ссылки иным способом (таблицы ID, относительные смещения, ARM/Thumb конструкции). Требуется исследование в Ghidra.

## Как повторить на macOS (только компьютер)

```bash
python3 tools/decode_nikon_package.py ~/Desktop/D3300_0102.bin -o ~/Desktop/d3300-analysis
python3 tools/d3300_lab.py inspect ~/Desktop/d3300-analysis/b860_102.bin
python3 tools/d3300_recon.py anchors ~/Desktop/d3300-analysis/b860_102.bin --verbose
python3 tools/d3300_elf.py ~/Desktop/d3300-analysis/b860_102.bin -o ~/Desktop/d3300-analysis/d3300_analysis.elf
```

После этого `.elf` можно импортировать в Ghidra как ARM little-endian. ELF предназначен исключительно для статического анализа, не прошивается и не исполняется на D3300.

## Что нужно для цели «Magic Lantern на D3300»

1. Разметить настоящий ARM/Thumb CFG и границы исполняемых участков; отделить код от таблиц/графики.
2. По результатам дизассемблирования найти реальный обработчик кнопок/событий и последовательность отрисовки OSD, подтвердить cross-references.
3. Изучить процедуру загрузки/проверки обновлений и возможность восстановления *до* любого эксперимента с собственным кодом.
4. Спроектировать и проверить минимальное внедрение вне живой камеры, насколько позволяют доступные инструменты. Реального симулятора EXPEED4 в этой работе нет.
