## B firmware — карта кода

- CPU: ARMv7 little-endian.
- ROM/base: `0x90020000`.
- Вектор старта: в заголовке B по смещению `0x20` хранится адрес `0x90352FE0`.
- По адресу `0x90352FE0` — ARM инструкция `LDR PC, [PC, #0x1E0]`; это переход к `0x90352FE8` (по литерному слову на `0x903531C8`).
- По адресу `0x9035303C` — `BIC R2, R2, #3`, по адресу `0x90353040` — `BL 0x903532A0`. Дизассемблирование `0x903532A0..0x903532DC` показывает цикл `LDM/STM`, затем цикл `LDR/STR` по 4 байта и `BX LR`. Это подтверждённая процедура копирования выровненных слов, вызываемая для перечисленных ROM→RAM диапазонов.

Реально присутствующие ROM→RAM копирования, ранее указанные Nikon Hacker:

| ROM (источник) | RAM (цель) | Размер | Предполагаемое назначение |
|---|---|---:|---|
| `0x9158A358` | `0x10000000` | `0x3B5B4` | kernel code (rwx) |
| `0x915C590C` | `0x1003B5B4` | `0x179C` | data |
| `0x916A73A0` | `0x1011D420` | `0x28B3C` | data |
| `0x916A739C` | `0x1011D03C` | `0x4` | data |

## Обработчики событий и кнопок

Образ смешивает A32 и Thumb-2. Адреса ниже проверены GNU objdump и Capstone на B-образе с указанным SHA-256. Связи классов получены через RTTI, таблицы виртуальных методов и cross-references.

| Узел | Подтверждённый путь | Вывод |
|---|---|---|
| RelayEventTask | `0x900223A4` → `0x90027036`; worker `0x90026FF1`; `BLX R0` в `0x9002702C` | очередь вызывает зарегистрированные callbacks |
| RelayEventTaskEx | `0x900223AC` → `0x900271E4`; worker `0x900271A5`; `BLX R0` в `0x900271DA` | расширенная очередь использует тот же механизм |
| Generic button | RTTI `COPNOButton` `0x91508BAD`; vtable `0x91516630`; method `0x9013CF56` | нормализация событий с ID `0x40..0x4D` |
| Shutter button | RTTI `COPNOShutterButton` `0x9150BB3F`; vtable `0x91521CFC`; method `0x9013DB1E` | обработчик читает ID и payload события затвора |
| Queued buttons | RTTI `COPNOQueueButton` `0x9150A8B3`; vtable `0x9151DE6C`; method `0x9013DDCC` | обработчик событий `0x04..0x15` |
| Application controller | RTTI `CSYSCAppButtonController` `0x91510DE3`; vtable `0x91538D1C`; constructor `0x90327520`; loop `0x9032760C` | получает записи очереди; `0x903276B4` передаёт запись в `0x903512A0` |

Инициализация `COPNOQueueButton` видна серией вызовов `0x9013DD94` в диапазоне `0x900FDD6C..0x900FE06A`. Это похоже на создание набора объектов физических органов управления. Статический анализ пока не связывает конкретные объекты с кнопками MENU и OK.

Полная машиночитаемая фиксация доказательств находится в `reports/verified-event-button-paths.json`. Ghidra-скрипт `ghidra/D3300_Mark_Event_Button_Candidates.py` проверяет ожидаемые байты и создаёт девять закладок.

## Потенциальные точки интеграции

| Адрес | Наблюдаемая граница | Оценка |
|---|---|---|
| `0x9002702C` | косвенный вызов RelayEvent callback | естественная callback-граница; ABI регистрации и lifetime неизвестны |
| `0x900271DA` | косвенный вызов RelayEventEx callback | аналогичная callback-граница; ABI регистрации и lifetime неизвестны |
| `0x9013CF56` | общий метод нормализации кнопок | полезен для изучения меню; физические коды MENU/OK не установлены |
| `0x903276B4` | передача принятой записи AppButtonController | центральная точка наблюдения; структура записи восстановлена частично |

Это кандидаты для дальнейшего статического моделирования. Для каждого `hook_safety = unverified`. Свободное исполняемое место, требования к ARM/Thumb interworking, сохранению регистров, кешам, RTOS-контексту и восстановлению пока не установлены.

## Дополнительные ориентиры в образе

Найдены *строки*, не доказанные исполняемые вызовы или интерфейсы API:

| ROM | Строка | Комментарий |
|---|---|---|
| `0x90027190` | `RelayEventTask.cpp` | полезный ориентир для анализа событий |
| `0x9003DCF0` | `JpegDriver.cpp` | полезный ориентир для JPEG-пайплайна |

| `0x90A9202D` | `TXT_1_Sht_List18_IntervalTimerShooting` | строка из набора ресурсов; **не доказательство доступного интервального режима** |

Строка `RelayEventTask.cpp` встроена рядом с Thumb-кодом диагностических сообщений. Прямого указателя на начало строки нет, поэтому одна строка не была основанием для адресов обработчиков.

## Как повторить на macOS (только компьютер)

```bash
python3 tools/decode_nikon_package.py ~/Desktop/D3300_0102.bin -o ~/Desktop/d3300-analysis
python3 tools/d3300_lab.py inspect ~/Desktop/d3300-analysis/b860_102.bin
python3 tools/d3300_recon.py anchors ~/Desktop/d3300-analysis/b860_102.bin --verbose
python3 tools/d3300_elf.py ~/Desktop/d3300-analysis/b860_102.bin -o ~/Desktop/d3300-analysis/d3300_analysis.elf
```

После этого `.elf` можно импортировать в Ghidra как ARM little-endian. ELF предназначен исключительно для статического анализа, не прошивается и не исполняется на D3300.

## Что нужно для цели «Magic Lantern на D3300»

1. Разметить настоящий ARM/Thumb CFG и границы исполняемых участков; отделить код от таблиц/графики.
2. Связать объекты `COPNOQueueButton` с физическими MENU/OK и найти последовательность отрисовки OSD.
3. Изучить процедуру загрузки/проверки обновлений и возможность восстановления *до* любого эксперимента с собственным кодом.
4. Спроектировать и проверить минимальное внедрение вне живой камеры, насколько позволяют доступные инструменты. Реального симулятора EXPEED4 в этой работе нет.
