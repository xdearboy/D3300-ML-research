# Полный аудит и доказательная трассировка 13 call-sites регистрации `0x900272A6`

- **Файл прошивки:** `b860_102.bin`
- **SHA-256:** `c7eb89f1a8e699fdd92c907989682d6d8746a46648436137cbd7e138f9afc3ff`
- **Базовый адрес ROM:** `0x90020000`
- **Диспетчер событий:** `RelayEventTaskEx` (`0x900271A4`, объект в RAM `0x10121EA8`)
- **Статус:** Статический аудит. Без модификации прошивки, без патчей и без выполнения кода на камере.

## 2. Порядок инициализации в `DriverInit.cpp`

Инициализация драйверов выполняется в `0x900223A0..0x90022600` в следующем строгом порядке:
1. `0x900223AC`: `bl 0x900271E4` — создание диспетчера `RelayEventTaskEx` и таблицы 32 слотов в `0x10121EA8`.
2. `0x900223BC`: `bl 0x90161760` — инициализация `KRMAIN` -> вызывает регистрацию #0 (`0x90161976`) -> **Слот 0** (`0x00000001`).
3. `0x900224C8`: `bl 0x900275AC` — инициализация `SdDriver` -> вызывает регистрацию #1 (`0x900275D8`) -> **Слот 1** (`0x00000002`).
4. `0x900224E8`: `bl 0x9011CAF0` — инициализация Serial/Display -> вызывает регистрацию #2 (`0x9011CA7C`) -> **Слот 2** (`0x00000004`).
5. `0x900224F0`: `bl 0x9011DAD0` — инициализация Input Forwarder -> вызывает регистрацию #3 (`0x9011DD78`) -> **Слот 3** (`0x00000008`).
6. `0x900224F8`: `bl 0x900E6A28` — инициализация Input Message Buffer (`0x1012090C`) -> вызывает регистрацию #4 (`0x900E6A74`) -> **Слот 4** (`0x00000010`).
7. `0x90022538`: `bl 0x90039FBA` — инициализация `DspDriver` -> вызывает регистрацию #5 (`0x9003A006`) -> **Слот 5** (`0x00000020`) и регистрацию #6 (`0x9003A010`) -> **Слот 6** (`0x00000040`).
8. `0x90022560`: `bl 0x9016255A` — инициализация `USBMAIN` -> вызывает регистрацию #7 (`0x90162596`) -> **Слот 7** (`0x00000080`), затем вызывает `0x90122524` (`15CUsbDongleCycle`), регистрирующий #8 (`0x90122534`) -> **Слот 8** (`0x00000100`) и #9 (`0x90122552`) -> **Слот 9** (`0x00000200`).
9. `0x90022584`: `bl 0x9015FC3C` — инициализация аудио подсистем:
   - `0x9015FD92: bl 0x90160DEE` (`I2SCH0`) -> вызывает регистрацию #10 (`0x90160DF6`) -> **Слот 10** (`0x00000400`).
   - `0x9015FDA2: bl 0x9002B96E` (`14CAudioAACCodec`) -> вызывает регистрацию #11 (`0x9002B920`) -> **Слот 11** (`0x00000800`).
10. `0x900225D8`: `bl 0x9011F1A6` — инициализация `Timer.cpp` -> вызывает регистрацию #12 (`0x9011F20E`) -> **Слот 12** (`0x00001000`).

## 5. Event Trigger Ledger (`0x90027316`)

Функция `0x90027316` передаёт идентификатор и маску в veneer `0x90225FD0`. Поведение согласуется с установкой event flag, но имя `tk_set_flg` и ABI здесь являются гипотезой, а не доказанным символом ROM:
```arm
90027316: 4601        mov     r1, r0              ; r1 = event_mask (flgptn)
90027318: 4804        ldr     r0, [0x9002732c]    ; [0x9002732c] = 0x10121EA8
9002731a: b510        push    {r4, lr}
9002731c: 6840        ldr     r0, [r0, #4]        ; r0 = flgid (идентификатор флага диспетчера)
9002731e: f1fe ef57   blx     0x90225FD0          ; runtime-target veneer; inferred event-flag role
90027322: 2800        cmp     r0, #0
90027324: d001        beq     0x9002732a
90027326: f06f 0001   mvn     r0, #1
9002732a: bd10        pop     {r4, pc}
```

## 6. Выводы для host-маршрутизатора меню

1. **Честный Input Event Ledger**:
   - Из всех 20 триггеров **только Триггер #8 (`0x9011E742`)** непосредственно связан с аппаратным опросом GPIO контакта (Pin 8) и пересылает сообщения в очередь диспетчера ввода `0x1011FFB4`.
   - Вторичный управляющий триггер **#7 (`0x900E6C5C`)** обрабатывает внешние пакетные команды (CEC-команды удалённого управления).
   - Все остальные 18 триггеров относятся к внутренним аппаратным подсистемам:
     - Карты SD (слот 1: триггеры 1, 3, 4);
     - Сопроцессор DSP (слоты 5, 6: триггеры 5, 6);
     - Очередь последовательного вывода/экрана (слот 2: триггер 19);
     - USB-контроллер и донгл (слоты 7, 8, 9: триггеры 10, 16, 20);
     - Аудиоподсистема (слоты 10, 11: триггеры 11, 17);
     - Датчики механики затвора/зеркала (слот 0: триггеры 12, 13, 14, 15);
     - Системный таймер (слот 12: триггер 9).

2. **Граница доказанности пассивного наблюдения**:
   - Статический аудит подтверждает только источник маски `0x00000008` и её передачу в dispatcher; вызов `tk_ref_flg` из внешнего наблюдателя и безопасный доступ к живой RAM камеры не найдены (**UNPROVEN**).
   - Доказанный безопасный вариант на текущем этапе — offline-парсинг read-only RAM snapshot через host-модель `dml_nikon_relay_snapshot`.
