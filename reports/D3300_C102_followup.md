# D3300 C 1.02 — кнопки, callbacks и графический буфер

Анализ выполнен на B-образе SHA-256 `c7eb89f1a8e699fdd92c907989682d6d8746a46648436137cbd7e138f9afc3ff`, база ROM `0x90020000`. Адреса инструкций ниже приведены без Thumb-бита. Результаты статические и относятся к этому образу.

## Объекты кнопок и структура записи

В `0x900FDD66..0x900FDF30` создаются объекты с идентификаторами, передаваемыми через R1. Например, в `0x900FDD68` загружается 1, а `0x900FDD6C` вызывает конструктор `0x9013DD94`. Последний вызывает `0x901AA73C` с R2=1. Через `0x902ADF86` R1 записывается как halfword в объект по смещению 0x10, R2 — по 0x12. В `0x900FDDE8` и `0x900FDDFA` для идентификаторов 8 и 9 вызывается другой конструктор `0x9013CDD0`, а в `0x900FDF3A` он вызывается для 0x1B.

В `0x9013DDCC` находится метод диспетчеризации очереди `COPNOQueueButton` (vtable `0x9151DE6C`). Он читает входной код кнопки из halfword `[R1]`, значение нажатия `value_1` из `[R1 + 4]` и исполняет `TBB [PC, R1 - 4]` для кодов `0x04..0x16`:
- Код `0x0B`: переходит на `0x9013DE14` (сквозное копирование записи без модификации).
- Код `0x0C` (OK/Activate): переходит на `0x9013DE00`, где проверяется `value_1 == 1`. При нажатии вызываются `0x9016E0A4` и `0x9016E076` -> `0x900E6B68`, упаковывающие 16-байтное сообщение `[0x00000002, ...]` и отправляющие его через μITRON системный вызов `snd_mbf(0x1012090C, msg, 0x10, 100)` в очередь GUI-событий `0x1012090C`. При отпускании (`value_1 == 0`) код `0x9016E088` отправляет сообщение отпускания `[0x00000003, ...]`.

На приёмной стороне очереди находится `CSYSCAppButtonController` (vtable `0x91538D1C`), создаваемый по адресу `0x90327520` как встроенный компонент `CSYSCAppManager` (Object 3 из `0x1012B6A0`, экземпляр в RAM `0x103DBFD8` по смещению `+0x5C4`). Он получает нормализованные события, упаковывает их в функции `0x903276C0` и вызывает проверенный шлюз записи `0x903512A0`, делая запись доступной для чтения через `0x9035128C`.

## RelayEventEx

`0x900272A6` принимает значение в R0, сохраняет его в первом свободном callback-слоте из 32 и при успехе возвращает связанное слово слота. При неуспехе возвращает 0. Вокруг поиска вызываются `0x90225F34` и `0x90225F3C`, их точный контракт здесь не установлен.

Конкретный вызов в `0x900275D6..0x900275E6` загружает Thumb-указатель `0x9002758B`, вызывает `0x900272A6` и сохраняет результат. Адрес callback указывает на код `0x9002758A`, который читает состояние и при ненулевом указателе вызывает `BX R3`. В worker `0x900271C8..0x900271DA` маска записи сопоставляется с полученной маской и происходит `BLX R0`. Регистрация является наблюдаемой внутренней границей, но время жизни, ошибки, контекст и допустимость стороннего кода не доказаны.

## Графический путь

Строка `DrawBuffer.cpp` находится по `0x9029EAD4` в пуле рядом с кодом. Функция `0x9029E940` использует индекс, проверяет его относительно 20, обращается к таблице по `0x104A0868` и вызывает через ARM-венир `0x90225A6C` адрес `0x100AC5B4`. Если второй аргумент ненулевой, вызывается венир `0x90225C50` → `0x100BE180` с кодом `0x3110`. Прямой Thumb-вызов в `0x90154642` и обработка результата далее проверены дизассемблированием.

`0x901547B2` вызывает `0x9029E9B2` с R1=4 и указателем в R2. Эта функция проверяет индекс и значение R1 относительно 6, затем вызывает тот же венир `0x90225C50` с параметром из таблицы `0x9147FAF4+0x28`. `0x901692F6` и `0x90169302` последовательно вызывают `0x9029EA3C` и `0x9029EB28`; первый код рассчитывает и сохраняет размеры, второй использует их при расчёте адресов. Это подтверждает путь управления буферами, но ещё не связывает его со штатным меню, форматом пикселей или публичным API рисования.

Числа `0x100AC5B4` и `0x100BE180` являются значениями литералов вениров. Их тела отсутствуют в известных ROM→RAM копиях, перечисленных в v0.3. Назначение и исполняемость этих RAM-адресов не подтверждены.

## Повторение

После извлечения B-образа и создания ELF:

```sh
python3 tools/d3300_recon.py refs b860_102.bin --target 0x900272a6 --isa thumb --mode branches
arm-linux-gnueabi-objdump -d -M force-thumb --start-address=0x900275d6 --stop-address=0x900275e8 d3300_analysis.elf
arm-linux-gnueabi-objdump -d -M force-thumb --start-address=0x90327628 --stop-address=0x903276bc d3300_analysis.elf
arm-linux-gnueabi-objdump -d -M force-thumb --start-address=0x9029e940 --stop-address=0x9029e994 d3300_analysis.elf
```

Поскольку ELF помечает всю ROM как код, таблицы и литеральные пулы не следует принимать за инструкции. Для разработки адаптера по-прежнему нужны доказанное соответствие кнопок, контракты очереди и графического интерфейса, а также модель потока исполнения.
