# Статический аудит и доказательная трассировка прошивки Nikon D3300 (C 1.02)

- **Файл образа:** `b860_102.bin`
- **SHA-256:** `c7eb89f1a8e699fdd92c907989682d6d8746a46648436137cbd7e138f9afc3ff`
- **Базовый адрес ROM:** `0x90020000`
- **Целевая архитектура:** Mixed ARM A32 / Thumb-2 (ARMv7-A/R)
- **Статус исследования:** Чистый статический аудит без внедрения патчей и выполнения модификаций.

## 2. CSTBLInfoView (`13CSTBLInfoView`)

### 2.1. Конструктор, фабрика и Call-Sites
- **Конструктор:** `0x901F9CEC` (Thumb-2). Размер объекта `0x19C` (412 байт).
  - Vtable базы: `0x91519194`
  - Суб-интерфейсы: `0x9151929C` (`+0x18`), `0x915192B8` (`+0x1C`), `0x915192C4` (`+0x20`)
- **Фабричная функция:** `0x901F9E10` (Thumb-2). Выделяет конверт `0x1F4` (500 байт) из пула кучи #5 (`0x900F01A8`) и вызывает конструктор через `b.w 0x901F9CEC`.
- **Call-Site фабрики:** `16CSTBLViewCreator` (vtable `0x9151EB04`), метод `0x900333BE`. Диспетчеризация осуществляется инструкцией `tbb [pc, r1]` на адресе `0x900333D8`, ветка `0x900333E6: b.w 0x901F9E10`.
- **Уровень уверенности:** **PROVEN**

### 2.2. Поток данных и взаимодействие с моделью
- В диапазоне кода `13CSTBLInfoView` (`0x901F9CEC .. 0x901FD860`) **нет ни одного обращения** к слотам `0x104B9044`, `0x104B9050`, `0x104B9054`, таблице `0x914ED324` или vtable `0x9152826C`.
- Представление `13CSTBLInfoView` взаимодействует только с объектом базового отображения (`[r0 + #0x24]`) через `0x902593C4`, передавая строковые теги UI-компонентов:
  - `"STBLOT12"` (`0x913CBA0B`)
  - `"STBLOT11"` (`0x913CBA02`)
  - `"STBLMP05"` (`0x913CB9E7`)
  - `"STBLMP04"` (`0x913CB9DE`)
  - `"STBLOT03"` (`0x913CB9F9`)
- Единственный RAM-литерал внутри `13CSTBLInfoView`: `0x1010778C` (внутренний дисплейный контекст).
- **Связь с UI-строками:** Строки `TXT_1_Bottom_Line1_Shutter_Speed` (`0x90EE70E6`), `TXT_1_Bottom_Line1_Aperture` (`0x90EE703E`), `TXT_1_Bottom_Line1_ISO_Sensitivity` (`0x90EE6F8F`) **не имеют ни одного 4-байтного pointer-xref в ROM**; они упакованы в упакованный словарь ресурсов. Прямая связь вызовов с `13CSTBLInfoView` отсутствует.
- **Уровень уверенности:** **UNPROVEN**

### 3.1. Генератор векторных команд `0x903111BC`
- **Адрес функции:** `0x903111BC`
- **Режим исполнения:** Thumb-2
- **Дизассемблирование:**
```arm

903111be: 6810         ldr     r0, [r2]           ; r0 = *count
903111c0: 881e         ldrh    r6, [r3]           ; r6 = X coordinate (uint16)
903111c2: 9c04         ldr     r4, [sp, #0x10]    ; r4 = palette / style index (stack arg)
903111c4: eb00 0580    add.w   r5, r0, r0, lsl #2 ; r5 = count * 5
903111c8: 1c40         adds    r0, r0, #1         ; count++
903111ca: f821 6015    strh.w  r6, [r1, r5, lsl #1] ; store X at [r1 + count * 10]
903111ce: eb01 0145    add.w   r1, r1, r5, lsl #1 ; r1 = target primitive address
903111d2: 885d         ldrh    r5, [r3, #2]       ; Y coordinate
903111d4: 804d         strh    r5, [r1, #2]       ; store Y
903111d6: 889d         ldrh    r5, [r3, #4]       ; Width
903111d8: 808d         strh    r5, [r1, #4]       ; store Width
903111da: 88db         ldrh    r3, [r3, #6]       ; Height
903111dc: 80cb         strh    r3, [r1, #6]       ; store Height
903111de: 720c         strb    r4, [r1, #8]       ; store palette/style attribute
903111e0: 6010         str     r0, [r2]           ; *count = count
903111e2: bd70         pop     {r4, r5, r6, pc}
```

### 3.2. ABI и структура векторного примитива
- **Размер (stride):** Строго 10 байт (`(count * 5) * 2`).
- **Формат полей:**
  - `+0x00`: `X` (uint16, ldrh/strh)
  - `+0x02`: `Y` (uint16, ldrh/strh)
  - `+0x04`: `Width` (uint16, ldrh/strh)
  - `+0x06`: `Height` (uint16, ldrh/strh)
  - `+0x08`: `Palette/Attribute` (uint8, strb)
  - `+0x09`: **Reserved / Unwritten** (байт не записывается данной функцией; семантика: **UNPROVEN**)
- **Аппаратная часть:** В прошивке отсутствует прямой call-chain, доказывающий использование выделенного «hardware rasterizer EXPEED 4». Командный список обрабатывается программной очередью буферов кадра. Статус утверждения о hardware-растеризаторе — **UNPROVEN**.

### 4.2. Таблица ветвей TBB (`0x04 .. 0x15`)
- Индексы `0x00..0x06` (коды `0x04..0x0A`): смещение `0x09` -> ветка `0x9013DDFE: b 0x9013DE14` (пропуск/дефолт).
- Индекс `0x07` (код `0x0B`): смещение `0x16` -> ветка `0x9013DE14` (прямое копирование 8 байт `ldrd r0, r1, [r5, #4]` в `[r7, #4]`).
- Индекс `0x08` (код `0x0C`): смещение `0x0c` -> ветка `0x9013DE00` (проверка `cmp r0, #1`, вызовы guard-функций `0x9016E0A4` и `0x9016E076`).
- Индексы `0x09..0x11` (коды `0x0D..0x15`): смещение `0x16` -> ветка `0x9013DE14` (прямое копирование).

## 5. Callback / Hook Seams

### 5.1. Диспетчеры событий RelayEvent
В подсистеме событий реального времени работают два параллельных диспетчера callback-слотов:

1. **One-Shot Dispatcher (`0x9002702C`):**
   - Задача: `RelayEventTask` (`0x90026FF0`)
   - База массива в RAM: `0x10121D94` (слоты начинаются с `+0x0C` = `0x10121DA0`)
   - Количество слотов: 32 (`0x20`), шаг 8 байт: `[uint32 bitmask, void (*callback)(void)]`
   - Инструкция вызова: `0x9002702C: blx r0`
   - **Особенность жизненного цикла:** Перед вызовом выполняется `0x9002702A: str r7, [r1, #4]` (где `r7 = 0`), что **очищает слот до выполнения callback**. Повторный вызов невозможен.
   - **Уровень уверенности:** **PROVEN**

2. **Persistent Dispatcher (`0x900271DA`):**
   - Задача: `RelayEventTaskEx` (`0x900271A4`)
   - База массива в RAM: `0x10121EA8` (слоты начинаются с `+0x0C` = `0x10121EB4`)
   - Количество слотов: 32 (`0x20`), шаг 8 байт.
   - Инструкция вызова: `0x900271DA: blx r0`
   - **Особенность жизненного цикла:** Очищающий `str` отсутствует. Слот сохраняется активным между событиями.
   - **Уровень уверенности:** **PROVEN**

### 5.2. Оценка безопасности внедрения (Hook Safety Boundary)
- **Пассивное наблюдение (Observation):** Возможно и безопасно путем прямого инспектирования состояния RAM-таблиц `0x10121DA0` и `0x10121EB4`.
- **Активный перехват (In-place Hooking):** **UNPROVEN**. Диспетчеры работают в многозадачной среде без блокировок слотов при обходе; перезапись указателей на лету сопряжена с рисками race condition и исчерпания стека прерываний.

## 7. T-Kernel / Allocator

### 7.1. Диапазон системных вызовов T-Kernel (ARM A32)
- **Точные границы диапазона:**
  - `first_stub`: `0x90225004`
  - `last_stub`: `0x90226060`
  - Суммарное количество: строго 471 stub.
- **Инструкция перехода:** `0xE51FF004` (`ldr pc, [pc, #-4]`).
  - В 32-битном режиме ARM значение `PC` опережает текущую инструкцию на 8 байт.
  - При выполнении инструкции по адресу `A` вычисляется `(A + 8) - 4 = A + 4`.
  - Загрузка адреса перехода происходит из слова, расположенного сразу за инструкцией (`A + 4`).
- **Целевые адреса перехода:** 467 stubs ссылаются на векторы в RAM (`0x10000000 .. 0x10100000`), инициализируемые диспетчером T-Kernel при старте. 4 stubs ссылаются на резервные ROM-обработчики (`0x90025A49`, `0x902EB6A1`, `0x9030D2BD`, `0x90274B6D`).
- **Уровень уверенности:** **PROVEN**

### 7.2. Системный аллокатор
- Функция: `0x900F01A8` (`heap_alloc(size, pool_id)`)
- Пул UI-объектов и представлений: `pool_id = 5` (используется фабрикой `0x901F9E10` для `13CSTBLInfoView`).
- **Уровень уверенности:** **PROVEN**

## 8. Архитектура интеграции (Исследовательская модель)

Ниже представлена исключительно концептуальная модель безопасного взаимодействия для исследовательского стенда без адресов модификации прошивки:

```
┌─────────────────────────────────────────────────────────────┐
│                   Аппаратный уровень / RAM                   │
│   [0x104B9044..0x104B9180]         [0x10121DA0 / 0x10121EB4] │

└──────────────┬───────────────────────────────┬──────────────┘
               │                               │
               ▼ (Пассивное чтение)            ▼ (Пассивное чтение)
┌──────────────────────────────┐ ┌─────────────────────────────┐
│      Property Observer       │ │       Event Observer        │
│   Считывание снапшотов RAM   │ │   Мониторинг битовых масок  │
└──────────────┬───────────────┘ └─────────────┬───────────────┘
               │                               │
               └───────────────┬───────────────┘
                               ▼
               ┌───────────────────────────────┐
               │    Simulator Module Bridge    │
               │   (Изолированный хост-слой)   │
               └───────────────┬───────────────┘
                               ▼
               ┌───────────────────────────────┐

               │  Формирование 10-байтных      │
```

1. **Property Observer:** Не вмешивается в процесс `memcpy` на `0x9019DE46`, производит чтение RAM-слотов `0x104B9044 .. 0x104B9180` только в фазах завершения кадровой синхронизации.
2. **Event Observer:** Производит аудит активных флагов в `[0x10121DA0]` и `[0x10121EB4]` без модификации адресов функций.
3. **OSD Command Generator:** Генерирует примитивы в строгом соответствии с 10-байтным форматом (`0x903111BC`), резервируя байт `+0x09`.

## 9. Раздел неподтвержденных гипотез (UNPROVEN)

Следующие положения были проверены статическим анализом и признаны **не имеющими прямого доказательства в ROM**:

1. **Семантика слотов `0x104B9044`, `0x104B9050`, `0x104B9054` как выдержки, диафрагмы и ISO:** В прошивке доказан только факт их пакетной записи через `memcpy` на `0x9019DE46`. Прямой строковый форматтер или OSD-потребитель данных слотов не обнаружен.
2. **Связь `13CSTBLInfoView` со строками `TXT_1_Bottom_Line1_*`:** Указатели на строки отсутствуют в таблицах перекрестных ссылок ROM; прямая передача строковых литералов в отрисовщик не доказана.
3. **Аппаратный растеризатор EXPEED 4:** В бинарном коде отсутствует цепочка вызовов к аппаратному 2D-растеризатору; отрисовка OSD строится на очереди команд в память кадрового буфера.
4. **Безопасность прямого перехвата callback-слотов RelayEvent:** Из-за отсутствия блокировок при итерации по слотам в прерываниях и многозадачном планировщике безопасность динамической модификации указателей на лету не доказана.
5. **Связь `0x10491580` с модулем `FirmUpdate`:** Опровергнута. Связь возникла как артефакт соседства строк RTTI в пуле метаданных.
