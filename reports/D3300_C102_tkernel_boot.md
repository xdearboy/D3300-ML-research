# Nikon D3300 C 1.02 — T-Kernel RTOS и цепочка начальной загрузки

Анализ выполнен на B-образе B-firmware D3300 C 1.02 (SHA-256 `c7eb89f1a8e699fdd92c907989682d6d8746a46648436137cbd7e138f9afc3ff`), база ROM `0x90020000`.

---

## 1. Идентификация операционной системы: T-Kernel

В таблице системной конфигурации по адресу ROM `0x9154EE20` обнаружены стандартные параметры спецификации **T-Kernel** (TRON Forum / T-Engine):
- `TSysName`: **`T-Kernel`**
- Таблицы лимитов ресурсов RTOS:
  - `TMaxTskId` (максимальный ID задач)
  - `TMaxSemId` (семафоры)
  - `TMaxFlgId` (флаги событий)
  - `TMaxMbxId` (почтовые ящики)
  - `TMaxMtxId` (мьютексы)
  - `TMaxMbfId` (буферы сообщений `mbf`)
  - `TMaxPorId` (порты рандеву)
  - `TMaxMpfId` / `TMaxMplId` (пулы памяти фиксированного/переменного размера)
  - `TMaxCycId` / `TMaxAlmId` (таймеры и циклы)
  - `TSysStkSz`, `TKernelStkSz`, `TKernelHeapSz` (размеры стеков и кучи ядра)
  - `TMaxRegDev`, `TMaxOpnDev` (регистрация устройств)

Это подтверждает, что EXPEED 4 в D3300 работает под управлением **T-Kernel 2.0**. Системные вызовы ядра (veneers в диапазоне `0x90225A00..0x90226200`) реализуют стандартный ABI T-Kernel: `tk_cre_tsk`, `tk_sta_tsk`, `tk_snd_mbf`, `tk_rcv_mbf`, `tk_dly_tsk` и др.

## 2. Пошаговая цепочка начального старта (Reset Vector)

### Шаг 1: Reset Vector и первичный фильтр ядер (`0x90352FE0`)
- **`0x90352FE0`**: `LDR PC, [PC, #0x1E0]` -> безусловный переход на `0x90352FE8` (ARM A32).
- **`0x90352FE8`**:
  - `MCR p15, 0, r0, c9, c12, 0`: конфигурирование монитора производительности/кэша.
  - `MRC p15, 0, r0, c0, c0, 5`: чтение регистра MPIDR (Multiprocessor Affinity Register).
  - `AND r0, r0, #3`: извлечение ID процессорного ядра.
  - `CMP r0, #0; BNE 0x90353180`: если ядро не Core 0, оно уходит в бесконечный цикл энергосбережения `WFI` / `0x90353180`.

### Шаг 2: Копирование сегментов ROM → RAM (`0x90353040..0x903530B8`)
Вызовы функции `memcpy` (`0x903532A0`) копируют сегменты из ROM в RAM:
1. `0x9158A358` -> `0x10000000` (размер `0x3B5B4`, код ядра T-Kernel)
2. `0x915C590C` -> `0x1003B5B4` (размер `0x179C`, данные ядра)
3. `0x916A73A0` -> `0x1011D420` (размер `0x28B3C`, данные подсистем)
4. `0x916A739C` -> `0x1011D03C` (размер `0x4`, указатель вектора)

### Шаг 3: Переход на точку входа ядра в RAM (`0x903531B0`)
- Подготовка аргументов для старта ядра:
  - `R0`: базовый адрес конфигурации памяти
  - `R1`: верхняя граница доступной RAM
  - `R2 = 2, R3 = 0, R4 = 1`
  - `R12 = 0x100388E8` (адрес в сегменте ядра в RAM)
- **`0x903531B8`**: `BX R12` -> передача управления в RAM по адресу `0x100388E8`.

### Шаг 4: Настройка режимов CPU и стеков (`0x100388E8` / `ROM 0x915C2C40`)
Код ядра последовательно переключает регистр CPSR и выделяет стеки для каждого режима процессора ARM:
1. `MSR CPSR_fsxc, #0xD1` -> режим **FIQ** (установка `SP = R6`)
2. `MSR CPSR_fsxc, #0xD2` -> режим **IRQ** (установка `SP = R6`)
3. `MSR CPSR_fsxc, #0xD7` -> режим **ABORT** (установка `SP = R6`)
4. `MSR CPSR_fsxc, #0xDB` -> режим **UNDEF** (установка `SP = R6`)
5. `MSR CPSR_fsxc, #0xD3` -> режим **SUPERVISOR** (установка `SP` для ядра)
6. `MCR p15, 0, r7, c3, c0, 0`: настройка доменов доступа памяти (DACR = `0x1555`).

### Шаг 5: Инициализация ядра T-Kernel (`0x100010B4` / `ROM 0x9158B40C`)
- Вызов `0x915C2D08 -> BX R3` передаёт управление на `0x100010B4` (`sys_ini()` / `ker_ini()`).
- Ядро считывает статическую таблицу конфигурации `0x90918BD4` и создаёт базовые задачи T-Kernel.
- Затем запускается диспетчер задач T-Kernel и стартует задача `CSYSCManager` (`0x103DBBE4`) и менеджер приложений `CSYSCAppManager` (`0x103DBFD8`).

## 3. Выводы для разработки Magic Lantern (D3300-ML)

1. **Точная природа RTOS**: Nikon D3300 использует спецификацию **T-Kernel 2.0**, а не кастомный микрокод. Это открывает возможность прямого использования официальных заголовков T-Kernel для работы с семафорами, почтовыми ящиками (`mbf`) и задачами (`tk_cre_tsk`).
2. **Точка безопасного перехвата**:
   - Хук в `RelayEventEx` (`0x900272A6`) является стандартным механизмом подписки задач T-Kernel на системные события.
   - Межзадачные сообщения (включая события клавиш) передаются через буферы сообщений `tk_snd_mbf` / `tk_rcv_mbf`.
