# Доказательная трассировка Persistent Callback Dispatcher (`RelayEventTaskEx`)

- **Файл прошивки:** `b860_102.bin`
- **SHA-256:** `c7eb89f1a8e699fdd92c907989682d6d8746a46648436137cbd7e138f9afc3ff`
- **Базовый адрес ROM:** `0x90020000`
- **Модуль RTOS:** `RelayEventTaskEx.cpp` (строка на `0x9002733C`)
- **Статус:** Статический аудит. Без модификации прошивки, без патчей и без выполнения кода на устройстве. Имена `tk_*` ниже — мнемонические гипотезы по форме вызова; ROM доказывает адрес veneer и поток данных, но не экспортированное имя или ABI RAM-реализации.

---

## 1. Архитектура и сквозной путь событий

В прошивке Nikon D3300 C 1.02 реализован персистентный механизм рассылки системных событий на базе потока RTOS T-Kernel:
1. **Инициализация при загрузке:** Функция `0x900271E4` (вызывается из `0x900223AC`) создаёт семафор, флаг событий (`flgid`) и задачу `RelayEventTaskEx` с точкой входа `0x900271A4`.
2. **Регистрация подписчика:** Клиент вызывает `0x900272A6` с аргументом `r0 = callback_func_ptr`. Функция захватывает семафор, находит первый свободный слот `r4` (`slots[r4].func_ptr == 0`), записывает адрес колбэка в `slots[r4].func_ptr`, освобождает семафор и возвращает токен события `r0 = slot.mask = (1 << r4)`.
3. **Генерация события:** Источник вызывает `0x90027316` с `r0 = event_mask`. Функция читает ID из `[0x10121EA8 + 0x04]` и вызывает veneer `0x90025FD2`; наблюдаемая роль согласуется с установкой event flag.
4. **Ожидание и диспетчеризация:** Задача `0x900271A4` вызывает veneer `0x90025FB8`. Результирующая битовая маска читается из `[sp, #4]`; затем 32 слота проверяются через `tst`, а совпавший callback вызывается в `0x900271DA`.
5. **Персистентность:** В отличие от однократного диспетчера `RelayEventTask` (`0x9002702A`, который обнуляет слот `str r7, [r1, #4]` перед вызовом), в `RelayEventTaskEx` **слот не очищается**. Указатель на функцию остаётся в таблице постоянно.

## 2. Структура данных в RAM (`0x10121EA8`)

Объект расположен в `kernel_data_2` (RAM `0x1011D420..0x1014603C`, загружается из ROM смещения `0x016873A0` / адрес `0x916A73A0`):
- **Смещение структуры в RAM:** `0x10121EA8` (ROM образ: `0x916ABE28`, смещение файла `0x0168BE28`).
- **Суммарный размер:** 276 байт (`0x114`).

### 2.1. Заголовок (12 байт, `+0x00 .. +0x0B`)
| Смещение | Тип | Назначение | Инициализация в ROM |
|---|---|---|---|
| `+0x00` | `int32_t` | Task ID (`tskid`) | `0x00000000` (заполняется в `0x900271E4`) |
| `+0x04` | `int32_t` | Event Flag ID (`flgid`) | `0x00000000` (заполняется в `0x900271E4`) |
| `+0x08` | `int32_t` | Semaphore ID (`semid`) | `0x00000000` (заполняется в `0x900271E4`) |

### 2.2. Массив слотов (32 слота по 8 байт = 256 байт, `+0x0C .. +0x10C`)
- **Базовый адрес массива:** `0x10121EB4`
- **Каждый слот:**
  - `+0x00`: `uint32_t mask` — предопределённая битовая маска `(1 << i)`.
  - `+0x04`: `uint32_t func_ptr` — указатель на функцию (0 = свободен).

В бинарном образе ROM таблица масок уже пред-инициализирована:
- Слот 0 (`+0x0C`): `mask = 0x00000001`, `func = 0x00000000`
- Слот 1 (`+0x14`): `mask = 0x00000002`, `func = 0x00000000`
- Слот 2 (`+0x1C`): `mask = 0x00000004`, `func = 0x00000000`
- ...
- Слот 31 (`+0x104`): `mask = 0x80000000`, `func = 0x00000000`

## 4. Реальный ABI колбэков

1. **Регистры на входе `blx r0`:**
   - `r0`: содержит адрес самой функции колбэка (`slots[r4].func_ptr`), так как адрес загружался в `r0` перед переходом `blx r0`.
   - `r1`: содержит полную маску полученных событий `flgptn` (загружена из `[sp, #4]`).
   - `r2`, `r3`: не инициализируются в теле цикла (содержат мусорные значения).
2. **Фактическое использование в ROM:**
   - Все 9 зарегистрированных в ROM функций имеют фактическую сигнатуру `void (*)(void)`.
   - Ни одна функция не читает `r0` или `r1` как значащие параметры: `r0` немедленно перезаписывается в прологе либо регистры `r0..r3` просто пушатся на стек.
3. **Возвращаемое значение:**
   - Полностью игнорируется диспетчером. Сразу после возврата следует `adds r4, r4, #1`.

## 6. Возможность использования для пассивного наблюдения

- **Чтение состояния (Passive Inspection):** **ДОКАЗАНО ВОЗМОЖНО**.
  - Адрес таблицы в RAM фиксирован: `0x10121EB4`.
  - Внешний монитор или дамп памяти может безинвазивно прочитать все 32 слота (занятость, адреса активных функций и назначенные маски событий).
- **Динамический перехват событий без изменения указателей:** **НЕВОЗМОЖНО (UNPROVEN / INFEASIBLE)**.
  - Диспетчер `0x900271A4` не ведёт кольцевой буфер истории и не вызывает внешние хуки.
  - Без изменения одного из указателей `func_ptr` в RAM или без регистрации свободного слота (слоты 13..31 свободны) сторонний код не может получить управление в момент наступления события.
- **Безопасность регистрации нового слота:** **ТРЕБУЕТ ВЕРИФИКАЦИИ (UNPROVEN)**.
  - Свободные слоты 13..31 физически присутствуют, но для штатного перехвата требуется вызвать внутреннюю функцию регистрации `0x900272A6` с захватом семафора, что является модификацией состояния RAM.
